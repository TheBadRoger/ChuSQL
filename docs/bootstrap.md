# 安装引导与离线修复

[← 返回 README](../README.md)

本页面向安装和维护数据库的人员，帮助你初始化系统目录，并在服务无法启动时离线修复。`csql-bootstrap` 负责这两类操作。

系统目录保存账号、授权和类型等元数据，预写日志（WAL）保存可供恢复的写入记录。

> [!WARNING]
> 维护前停止使用同一数据目录的所有进程。当前版本通过数据目录锁协调维护，使用旧版进程的环境需由维护者确认进程已退出。

## 安装引导

使用以下命令初始化系统目录，`settings.toml` 替换为实际配置文件路径：

```sh
csql-bootstrap --config settings.toml --user root --password-stdin
```

口令从标准输入读取一行，哈希后保存。程序创建系统目录，启用可登录的最高权限身份（SUPERUSER），并登记现有内置类型。安装脚本调用此入口。重复引导保留已有口令和身份属性，拒绝冲突的类型定义及已降权的引导身份；需要免密初始化时显式加 `--passwordless`。

## 三种维护策略

按下表选择命令：

| 命令 | 行为 | 数据影响 |
| --- | --- | --- |
| `repair` | 修复已知系统表的目录结构、列定义及结构元数据 | 原有 `.db` 文件保持字节一致，WAL 和初始化数据保持不变 |
| `recover` | 修复结构、重放可用的已提交 WAL，补齐必要的初始化内容 | 可能改变系统表数据，尽量保留现有身份、口令与授权 |
| `reset` | 重建初始系统目录，创建指定管理员及内置类型登记项 | 清除原系统目录中的身份、口令、角色关系、授权及其他系统内容 |

`recovery` 是 `recover` 的兼容别名。三个命令都保留业务数据库目录；`reset` 后业务数据仍在，原访问授权已清除，需要重新创建身份并授权。

示例中的配置路径按实际位置替换：

```sh
csql-bootstrap repair --config settings.toml
csql-bootstrap recover --config settings.toml
csql-bootstrap reset --config settings.toml --user root --password-stdin
```

优先使用 `repair`。需要恢复数据、补内置类型或初始化管理员时，`repair` 会中止并提示改用 `recover` 或 `reset`，原系统目录保留。

初始化缺失管理员时，`recover` 需要 `--password-stdin`；已有管理员保留原口令。`reset` 需要口令输入选项或显式的 `--passwordless`。维护入口直接调用存储库，通过本机命令行离线运行，输出使用英文。

## 副本、备份与恢复边界

维护在副本中执行，成功后保留原系统目录备份再发布，失败时保留原目录和候选副本。备份包含账号哈希和授权，应妥善保护。

recover 依赖可用的已提交 WAL。历史记录缺失、数据页损坏或未知系统表可能需要完整备份；reset 会清空系统身份与授权。业务库的损坏需另行恢复。
