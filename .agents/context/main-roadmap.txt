ChuSQL 长期路线图

交付状态和验收只以 progress.txt 为准；近期顺序见 side-branch-plan.txt。
本文件描述目标，不代表现有实现或功能承诺。

目标链路：SQL → Parser / Binder → Typed IR → Planner / Optimizer → Executor → Rust Storage。
类型能力与权限保持独立；catalog 保存对象、依赖和语义，内核保留必要基础机制。

阶段
- A 类型与函数基础：稳定 TypeId / FunctionId、注册表、逻辑/物理类型分离、版本化值；验收见 progress.txt。
- B 能力与运算（2–6）：Capability、Operator、Cast、Aggregate、参数多态与约束解析。
- C 复合与自定义类型（7–12）：ADT、Record/Composite、Newtype/Domain、参数化类型、Range、用户类型。
- D 函数与效果（13–16）：用户函数、Effect、纯 Generated Column、有副作用的 Trigger。
- E 权限与类型化查询（17–19）：权限 Capability、Query a、Rewrite / Optimizer 函数化。
- F 扩展：对象体系统一后实现 Extension 的版本、依赖、安装/升级/移除；其他访问方法按真实需求推进。

贯穿约束
- 现有 ColumnType / Expr / RelOp 有真实消费者；迁移时逐步收拢，不提前删除兼容桥。
- 每阶段验证持久化、升级、依赖和恢复，不能靠重新初始化掩盖不兼容。
- 内建对象可由可信 bootstrap 元数据恢复；用户对象依赖 WAL / 备份。
- catalog 版本与 bootstrap / recovery 匹配，系统目录索引可重建。
- 不提前增加孤立扩展或绕过事务、权限及依赖管理。
